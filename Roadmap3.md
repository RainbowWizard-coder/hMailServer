# Roadmap 3: everything the project had on GitHub, on GitLab

**Written 27 September 2026.** On 18 September 2026 GitHub suspended the account this project lived under. Everything it had published there has answered 404 since: the releases and their files, the container image on ghcr.io, the wiki, the issues, pull requests and discussions, the Actions workflows that built, signed, scanned and fuzzed it, and the update feed every server read. The project now lives at [gitlab.com/hmailserver/hmailserver](https://gitlab.com/hmailserver/hmailserver) (at `gitlab.com/Progressiverobot/hmailserver`, the owner's own namespace, until it moved into the group `hmailserver` on 29 September 2026), and 6.3.4 (27 September 2026) was its first release made off GitHub, by hand. The owner wants all of it back, on GitLab. This file maps what that takes, row by row: the owner's three items first, in the owner's words, then every other difference between what GitHub had and what GitLab has now, and the few things neither had that belong with them. Since the owner's "get all done lets get this everywhere" of the same day, section 9 adds every other channel people install mail servers from: registries, app stores, the distributions' own archives, the Windows and macOS package managers, home-server stores, cloud marketplaces and indexes.

Nothing here is taken from GitHub, and no row downloads from it, runs on it or submits to it. What GitHub had is read from the project's own git history - the last master pushed there is `cb098c9ba` (18 September 2026), and the GitHub workflow files, unchanged from `6399e08a5` on, stayed in the tree until `6593259e0` removed them on 26 September 2026 - and from the GitHub releases, which were re-hosted byte for byte on GitLab on 24 September. What GitLab has is read from branch `batch41` at `1c68d5191` (merge request !1 lands it on master, which is at `6bc09509d`), from the GitLab project (id 86730559) through read-only API calls, and from the project's public sites, all on 27 September 2026. Pipeline, job and issue numbers are GitLab's unless a row says otherwise.

[Roadmap.md](Roadmap.md) is the record and [Roadmap2.md](Roadmap2.md) the product's programme after 6.3.2. This file is narrower: what a user could download, verify and install before 18 September, what the project ran to make and check it, and what stands between that and GitLab today. Four of its rows share ground with Roadmap2 rows - *Windows on ARM*, *The release chain off a single forge*, *`winget install hMailServer` (and Chocolatey)* and *macOS*. Roadmap2's row keeps the product's side, and the two are flipped together. A row that is done moves to Roadmap.md with the measure that says so.

The legend is Roadmap.md's: ✅ done and verified, 🔄 underway, ⬜ not started, ⏸️ deferred with the reason written down. A row is ✅ only when it is true on GitLab today. Each row says what GitHub had and where that is recorded, what GitLab has now (built, published, where), what is left, what it depends on, and **Done when:** - a check anyone can repeat. Section 9's rows cover channels neither forge had, so each says instead whether the channel fits a mail server, how a project gets in and who builds, and what this project must build. **Owner:** marks an input only the owner can give: a key, an account, a decision or a machine. ## 1. The owner's three items

The owner's note, checked against the history first:

- *"AArch64 .deb .rpm, AppImage, and ARM64 Windows installer."* The AArch64 `.deb` and `.rpm` and both AppImages were on the GitHub releases 6.3.0 to 6.3.3. GitLab CI now builds and installs the packages and builds and tests both AppImages - every one of those jobs passed in 6.3.5's tag pipeline and in `batch42`'s pipelines of 30 September 2026 - and 6.3.6, published by its tag pipeline 2914690858 on 6 October 2026, is the first release since 6.3.3 to carry them: the AArch64 `.deb` and `.rpm` under their generic names and for each distribution release, and both AppImages with the sources of the libraries they carry. An ARM64 Windows installer never existed on GitHub: it was first compiled on 26 September 2026, it is new work, and 6.3.6 carries the first, `hMailServer-6.3.6-arm64.exe`, Authenticode-signed, which no ARM64 machine has run yet.
- *"No container image."* Right. GitHub had `ghcr.io/progressiverobot/hmailserver` for 6.3.2 and 6.3.3, amd64 only and unsigned. Since 6 October 2026 the GitLab registry has 6.3.6's image, for linux/amd64 and linux/arm64, pushed, signed and started by the release's own tag pipeline (the container image row below).
- *"apt and dnf repository, winget and Chocolatey package of this project's in the public repositories."* None of the four existed on GitHub. At `cb098c9ba`, `hmailserver/docs/PackageManagers.md` says under "What this does not do": "an apt or dnf repository, and the Arch AUR, are separate roadmap rows". The winget and Chocolatey templates and their workflow were added in `6fc7ae91c` on 15 September 2026, after the `v6.3.3` tag; no release ever ran the workflow, and nothing was submitted. They are here because the owner wants them.
