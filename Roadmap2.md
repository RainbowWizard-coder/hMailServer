## 9. End-to-end encryption

Transport is done: TLS everywhere, DANE, MTA-STS, a post-quantum key exchange, and S/MIME in the page since 11 September. What is not done is mail that stays unreadable to the server itself, and to anyone who takes the server. Proton and Tuta built businesses on that; theirs is proprietary in the sense that only their client reads their format. This server's version is built on OpenPGP, so that any client with a key reads the mail and no one is locked in - the standard is the feature. Roadmap.md deferred OpenPGP in the browser on 11 September as "the S/MIME page's design on another format"; it is un-deferred here, as the first row of the four.

## 13. The settings themselves

Where a setting lives, who may change it, when it takes effect and what it was before. The server has two
tables: `hm_settings`, which the COM `Settings` object and the Control Panel's classic pages have always
used, and `hm_inisettings`, which since schema 6042 holds the 241 keys the `[Settings]` section of
`hMailServer.ini` used to be the store for. **That flip has landed** (the first row below): the database
decides, the file's section is a cache the server rewrites at every start, a value edited into it is named
in the error log and put back, and a `[SettingsOverride]` section is the deliberate door for a database that
is unreachable or wrong. The rows below it are what that store makes possible and was blocking.

| ✅ | **The database is the settings store; the file is the bootstrap** | **Landed at schema 6042.** The rule since 15 September 2026, that a new setting goes in the database and no new key is added to `[Settings]`, is in `.github/CONTRIBUTING.md`, where a contributor meets it. `build/check-ini-coverage.py` now holds it against a committed baseline (`build/ini-settings-baseline.txt`, 266 keys across five sections, each with the default the server reads it with): a new `[Settings]` key fails CI with the rule quoted and `hm_settings` named, and a new bootstrap key is allowed with the baseline updated in the same commit.
