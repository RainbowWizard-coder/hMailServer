# Every hMailServer.INI key the server reads through IniFileSettings, as of the day
# the database became the settings store.
#
# THIS FILE IS A RULE, NOT AN INVENTORY. The rule, from 15 September 2026 and
# written where a contributor meets it in .github/CONTRIBUTING.md, is that a
# SETTING BELONGS IN THE DATABASE: in hm_settings, reached through Property and
# PropertySet, with a Control Panel editor. No key is added to [Settings] here.
#
# build/check-ini-coverage.py compares this list with the keys IniFileSettings.cpp
# actually reads and fails when they differ, so a new [Settings] key cannot land
# without somebody deleting a line from this file and being asked why.
#
# The other three sections are the bootstrap - how the database is reached, and how
# an administrator is let in without one - and they are where a key that genuinely
# has to be readable before the database is open belongs. Adding one is allowed:
# add it here in the same commit, and say in the commit message why it cannot wait
# for the database.
#
# It is also where the SHIPPED DEFAULT of each key lives. The default is the third
# argument of the read in IniFileSettings.cpp - it has always been there, and until
# now nothing but the reader saw it - and it is what an installation is compared
# against to answer "which of these settings is not what this version ships with":
# /api/v1/settings/changed, Settings.GetChangedFromDefault over COM, `hmctl config
# changed`, and the Deck's Changed from stock page. The same check fails when a
# default is edited in the source and not regenerated here, because a list of what
# has been changed that compares against last month's defaults is confidently wrong.
#
# One "Section Key Kind Default" per line, four whitespace-separated fields. Kind is
# "integer" where the server reads the key with GetPrivateProfileInt, which stops at
# the first character that is not part of a number - so a stored "0009" is the same
# setting as a default of 9 - and "string" where it reads the text. Default is JSON
# encoded, so that an empty default is a token rather than a missing column.
# Regenerate with:
#   python3 build/check-ini-coverage.py --write-baseline
