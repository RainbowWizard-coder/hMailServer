# What the source tarball, hmailserver-<version>.tar.gz, leaves out of the tree
# (build/ci/source-tarball.sh; hmailserver/docs/SourceTarball.md). One list, and
# the only one: Debian's Files-Excluded, the RPM spec and the Guix snippet are all
# made from it, and build/check-source-tarball.py holds a tarball to it.
#
# The format, so that each of those can read it without a parser of its own:
#   - one path per line, relative to the top of the tree, with no leading "./"
#     and no trailing "/"; a directory stands for everything below it;
#   - the path is literal: no wildcard, no quoting, no escape. A space is part of
#     the path. Debian's Files-Excluded is separated by white space, so a space is
#     written there as "?" (build/check-source-tarball.py --files-excluded prints
#     the field);
#   - "#" starts a comment line, and blank lines are ignored;
#   - the file is checked out with LF line endings on every platform
#     (.gitattributes), because shell reads it.
#
# What is left out, and the rule: a path is here when the Linux build, its tester
# programs, its packages and the Linux suite never read it (the CMake build of
# hmailserver/source/Server/CMakeLists.txt, build/ci/linux-build.sh and
# build/ci/linux-suite.sh), AND it is either not free or used only by the Windows
# build and its installer. build/check-source-tarball.py holds the first half to
# what those three files name - and the suite's project, the other Linux jobs'
# scripts (packages, fuzzing, cross, sanitizer, coverage, repro) and what the build
# and the suite read at run time - every time the checkers run.
